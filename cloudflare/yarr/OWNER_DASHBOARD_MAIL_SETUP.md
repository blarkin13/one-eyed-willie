# Yarr owner dashboard and mail — staged implementation
- Owner-only browser dashboard `https://yarr.media/owner/` and inbox `https://yarr.media/mail/`. Set `YARR_OWNER_ACCOUNT_ID` to the exact immutable Yarr user ID after verifying it through the private database (not a customer email, not a device credential).
- Four branded aliases: support, billing, privacy and legal @yarr.media. Use separate Yarr D1 records, private R2 bucket and scoped Resend sending key. Do not share Humperdinck's mail bucket, data or credentials.
- Existing public refund terms reference refunds@yarr.media. Preserve that address and verify forwarding; change published contact to billing only once billing is verified. Keep refunds as a compatibility forward if needed.
- Apply additive migration 0013 in a development copy first, then production only after tests. Create a private R2 bucket (no public URL); add `[[r2_buckets]]` with binding `MAIL_MESSAGES` and bucket_name `yarr-mail-private` to wrangler.toml only after provisioning. Use a distinct dev bucket/binding for tests.
- Set `SUPPORT_MAIL_FORWARD_TO` to the verified owner Gmail destination as a Worker secret; `RESEND_API_KEY` is a separate domain-scoped sending secret. Verify yarr.media in Resend and add required nonconflicting DNS records; do not overwrite root MX or existing SPF blindly.
- Inbox and replies are separately disabled unless `SUPPORT_MAIL_INBOX_ENABLED=true` and `SUPPORT_MAIL_SEND_ENABLED=true`. First configure each alias for direct Gmail forwarding. Test from an independent external account, then test one alias routed to the Worker (forward first, then private archival) with Gmail receipt, mailbox thread and downloaded original. Verify reply From and Reply-To, dedupe, foreign-origin rejection, owner/non-owner access, HTML safety, attachments, storage failure and rollback. Only then cut over four live aliases individually.
- Before storing production correspondence, approve retention/deletion/holds and backup/access rules, update privacy disclosure, and validate restore. No historical Gmail imports. No paid plan, live DNS or route change authorized by this PR.
- Dashboard reports DB aggregate accounts, connected devices, servers, purchased entitlement records and Stripe checkout amounts/statuses (not reconciled net revenue; test rows may be included). Website analytics and release downloads are not connected; no fabricated metrics. No customer media telemetry.
- Humperdinck source reference: PRs 224/226 and issue 227; inbound archiving there remained unverified at inspection. Reused bounded MIME and mail modules still require independent Yarr tests; original attachments are downloadable .eml, not rendered inline.
